# 预兆之屋 · House of Omens

四个午夜故事 · 原创宅邸探索试玩

新增组合触发和狼人剧本，数值、胜负条件与感染规则见 [狼人试玩说明](docs/werewolf-playtest.md)。正式开局默认未知故事，指定剧本移至折叠的测试入口。

后续方向与二、三版机制参考见 [后续规划与机制调研](docs/future-roadmap-and-mechanics-research.md)。文档区分已确认方向、原作规则与原创提案，其中未来功能尚未实现。

参考《山屋惊魂》第三版的阴暗宅邸、绘画房间和卡牌氛围制作的非官方 Demo。卡牌和四个剧本为原创，规则经过简化。人物与物品使用免费授权素材，来源及许可见 [美术素材说明](docs/art-assets.md)。

## 直接试玩

打开项目内的 `outputs/预兆之屋-demo.html` 即可离线游戏，如果文件不存在 执行`npm run build:portable` 构建生成，图片和规则全部包含在单个文件内。也可以在本目录运行 `node scripts/serve-demo.mjs`，访问 `http://127.0.0.1:4173/`。

存档保存在当前浏览器，未确认的卡牌、拼接预览和作祟提示也会保存。v2 使用独立存档；请重新开始一局体验新规则，旧版存档不会被覆盖。直接打开文件和本地网址的存档相互独立。

## 这一版怎么玩

需要快速验证作祟机制时，点击首页底部“定向测试”，选择剧本和测试场景，点击“进入作祟测试”。测试局准备好三层相通的 11 间房与吊坠、咖啡、绷带，只需确认一页说明即可操作。狼人另有治疗、即将转化和月印解咒场景。单人使用独立测试存档，支持保存／回到测试点，以及重置同一场景；联机房主可在开局时选择场景。普通新局仍从探索开始。详见 [快速作祟测试](docs/quick-playtest.md)。

- 选择 3–6 人探险队，默认根据预兆和房间组合揭晓剧本；也可在测试入口指定四个剧本之一。单人切换控制所有友方人物，电脑控制敌人。
- 每人有力量、速度、理智、知识四条独立数值轨。速度决定每回合移动力，其他属性参与对应检定；损失属性按轨道下降格数计算。
- 点击当前房间门外的探索标记，随机抽取适合本楼层的房间板块。预览并旋转，确认门对门后放下。地图没有预设网格边界；门对墙不能通行。
- 一楼、二楼、地下室分别拼接。楼层标签仅切换地图视图，人物必须抵达楼梯才能上下楼。地图支持缩放与滚动。
- 新房间的图标决定抽事件、物品或预兆。36 张房间板块、10 张事件、10 张物品、12 张预兆分别管理；旧房间不会重复抽牌。
- 抽卡立即停止本回合移动，但仍可攻击、使用物品或完成目标。事件有属性检定及成败效果，物品有被动加成或主动用途，预兆先结算效果再进行作祟检定。
- 作祟前，每抽一张预兆，用全队累计预兆数枚 0–2 点骰子进行检定，总点数达到 5 则触发作祟。骰子停稳后自动结算；剧情、阵营变化和新目标仍会展示，供玩家阅读后继续。
- 肉体伤害分配预览后统一确认到力量或速度，精神伤害分配到理智或知识。作祟前不会降至骷髅位；作祟后任一属性降到骷髅位，人物死亡。
- 每人每回合可攻击、目标互动和休整各一次。休整将一条受损属性恢复 1 格至起始上限，同时停止移动。结束所有人物行动后推进回合，作祟期间敌人沿实际连通的门和楼梯追击。

## 地图与掷骰交互（本轮）

- 地图铺满游戏背景。当前人物及完整属性轨、物品、结束行动按钮常驻正下方；全员状态位于左侧，章节、作祟和目标位于右上，手记按钮及窗口位于右下。楼层选项居中，人物头像排列在框外下方。更多行动和测试工具点击展开。窗口不会挤压地图，地图四周留有整屏拖动空间，并支持一键回到人物。
- 伤害分配默认填入一套方案，优先避免致命分配，再尽量减少能力数值损失。减号高亮；当伤害已分满时，点击减号会从另一项转移一点，不必先撤回。加号用于撤回。
- 新对局和恢复的单人存档使用交互掷骰：点击每组骰子右侧的小按钮投掷，动画结束才显示点数。投掷之前不会应用该次检定的后果。
- 掷骰弹窗有独立的“动画”和“自动投掷”开关。自动投掷只影响当前玩家负责的骰子；电脑敌人的骰子由主机自动投掷。
- 联机力量对抗双方分别投掷。玩家不能替对方投骰，也不能重复投已完成的骰子。守钟人的骰子归原叛变角色的座位控制，敌人移动仍按电脑规则进行。
- 所有骰子翻滚结束后先停留 1.4 秒展示点数，再由行动方自动结算，结果显示在骰子下方，无需再点击结算；联机自动同步。等待投掷、已投点数和待结算操作都随对局状态保存，刷新不会重投。

敌人回合先播放按门与楼梯逐房追猎的移动过程，再打开同室攻击检定；没有追到人物时也能看见移动。卡牌说明与效果按阶段、剧本、人物动态解析，作祟开始后预兆不再显示或执行作祟检定。接口和验证见 [动态卡牌与地图悬浮界面](docs/dynamic-cards-and-map.md)。

## 其他交互

- 抽房间改为地图旁的操作栏，支持拖拽吸附预览与旋转。地图始终可查看、拖动、缩放和切换楼层；“全图”适配当前楼层的完整地图。
- 顶栏及掷骰弹窗提供骰子动画开关，偏好保存在本机；关闭后直接显示结果。弹窗背景改成轻度遮罩。
- 伤害先分配预览，减号分配、加号撤回，轨道标记当前位置、受影响格子及确认后位置；剩余伤害归零后统一确认，致命分配有明确提示。
- 每轮开始单独提示全队移动力恢复，顶部行动条、人物卡和地图棋子共同标记当前角色。
- 当作祟骰最高点数不足 5（前两张预兆）时自动跳过检定，在预兆结算和记录中解释原因。

## 素材室与 DIY 草稿

顶栏“素材室”列出全部房间（含五张起始板块）、事件、物品、预兆、人物、剧本和标记。可以搜索、查看效果与属性轨，旋转预览房间，然后复制为自定义草稿。

草稿支持名称与文案编辑、房间楼层及门位编辑、图标与现有插画选择，保存到当前浏览器；支持 JSON 素材包导入、导出及基本格式校验。规则逻辑继承原组件，草稿暂不进入正式对局。后续可在此基础上增加效果编辑和自定义牌组。

## 局域网联机 · 第一阶段

1. 主机双击项目根目录的 `启动试玩.cmd`，保持窗口运行。如果当前已经在试玩，主机已经运行，无需重复启动。
2. 主机打开 `http://127.0.0.1:4173/`，先在单人大厅选好剧本和人数，再点击“联机”。
3. 联机页显示本机的局域网网址。把该网址给同一 Wi-Fi／局域网里的朋友；朋友必须打开同一台主机的网址，不能使用自己的 `127.0.0.1`。
4. 房主创建房间，朋友填写名字和六位房间码加入，各自选择角色，房主开始。未被认领的角色由房主代管，怪物由游戏规则控制。
5. 当前角色的玩家操作，公共剧情与回合提示由房主确认；状态约每 1.2 秒同步，主机检查操作权限和版本冲突。刷新同一浏览器页面可恢复房间身份和进度。

无需账号。主机程序关闭后房间消失；网络需允许设备互访及主机的 4173 端口。此阶段没有公网转发、长期联机存档、掉线代管或中途换人。主动离开会清除当前浏览器的联机身份；暂时断线请保留页面等待重连。

直接双击离线 HTML 时，可以单人游戏和管理素材；联机需要通过上述主机网址打开。联网双方的游戏规则由主机统一计算，不采用客户端提交的整份存档。

## 远程联机 · 灰度准备

联机大厅保留局域网入口。远程模式支持创建、六位房间码加入、无令牌邀请链接、连接状态、手动重连、刷新恢复和明确的版本/过期提示；进入游戏后沿用同一套座位、权限和操作界面。每个远程房间映射到一个 SQLite-backed Durable Object，支持按玩家投影广播、幂等重试、退避重连、HTTP 降级、24 小时过期和 Worker 重启恢复。

发布开关 `REMOTE_MULTIPLAYER_STAGE` 默认为 `preview`：普通用户只看到局域网，测试者可在已部署网址后加 `?network=remote` 主动进入远程大厅，邀请链接会自动显示远程入口并填入房间码。设为 `on` 后向所有用户显示远程入口；设为 `off` 时停止创建新远程房间，已有房间仍可加入、读取和继续游戏。该开关不是访问控制，预发布 Worker 应使用独立部署名，不要把测试地址当作私有地址。

远程入口包含按来源创建/加入限流、16KB 请求上限、同源校验、安全响应头和稳定错误码。身份令牌只在浏览器保留，服务端持久化 SHA-256 摘要；日志和房间指标不记录令牌或私密剧情正文。开发验证运行 `npm run test:remote`，该命令会构建并启动临时 Wrangler 服务，验证真实限流、6 人并发、双 WebSocket 同步、隐私投影、幂等、重启恢复、旧 schema 迁移、过期和关闭新建后的旧房间继续运行。部署前运行 `npm run release:check`。独立预发布已上线，跨网络完整试玩和生产灰度尚待验收，步骤见 [远程联机发布手册](docs/remote-release-runbook.md)。

## 四个剧本

- 第十三声钟响：一位探险者叛变，指挥其余队员完成三处祭坛封印。
- 镜中来客：调查古镜，找到并击败镜魇。空镜的银屑强化全队攻击。
- 深水之下：找到两枚保险丝、修复发电机，让所有幸存者回到一楼入口共同逃生。
- 月光照进来的时候：一名探险者转为狼王；好人通过治疗狼毒、封窗和净化月印争取解咒，或击败全部狼人。狼群通过感染转化、消灭好人或拖到血月倒计时结束获胜。

目标生成在已连通的房间内，按队伍人数和地图规模调整部分难度。作祟弹窗列出本局具体目标及所在楼层。

## Demo 的取舍

本版保留随机抽房间、旋转接门、三层探索、属性轨道、三类牌及作祟检定。为方便试玩，一楼探索三间非起始房间后优先抽出地下阶梯；采用简化战斗，敌方单次伤害上限为 3，允许休整。四个剧本和卡牌为原创，没有实现原版全部特殊规则、物品交易、官方剧本；现已加入局域网联机。

## 开发与验证

从零安装软件、配置依赖、启动开发服务及排查问题，见 [本地开发环境指南](docs/local-development-guide.md)。指南也包含离线打包、局域网试玩、Worker 本地验收和新增剧本／物品的代码入口。

开发新内容前请阅读 [剧本与物品机制扩展指南](docs/content-extension-guide.md)，了解剧本生命周期注册、物品能力定义和可恢复结算的边界。

使用 Node.js 22.13+，安装依赖后运行 `npm run dev`。构建使用 `npm run build`，规则验证使用 `node --test tests/*.test.mjs`，远程 Worker 持久化验收使用 `npm run test:remote`。构建完成后运行 `node scripts/build-portable.mjs` 更新离线单文件。

规则验证覆盖队伍与属性、随机抽取及旋转、门墙通行、楼层连接、卡牌实际效果、分步作祟提示、伤害分配、跳过不可能的作祟检定、素材包导入导出、联机身份与座位、双客户端冲突和刷新恢复、敌人寻路、目标可达、胜负和存档恢复；另包含三个剧本在 3 人和 6 人队伍下共 72 局合法动作通关模拟。模拟通过不代表任意策略都能获胜，也不替代人工交互试玩。

## 文件结构

- `app/page.jsx`：游戏界面、交互弹窗和浏览器存档。
- `app/game.css`、`app/revision.css`、`app/iteration-three.css`：视觉、动画与响应式布局。
- `app/workshop.jsx`、`lib/catalog.mjs`：素材浏览与自定义草稿。
- `app/network.jsx`、`scripts/room-server.mjs`：远程/局域网大厅、会话恢复与局域网主机同步。
- `lib/network/room-domain.mjs`：局域网与远程联机共用的房间权限、版本、幂等和投影内核。
- `lib/network/game-room-do.mjs`、`remote-rate-limiter.mjs`、`app/api/remote`：房间与限流 Durable Object、SQLite 指标和远程 HTTP / WebSocket 路由。
- `lib/network/network-protocol.mjs`、`remote-transport.mjs`：稳定消息外壳与浏览器远程传输适配器。
- `lib/game-data.mjs`：人物、房间、卡牌和剧本数据。
- `lib/game-engine.mjs`：独立的确定性游戏规则引擎。
- `lib/card-rules.mjs`：按阶段、剧本和人物解析与修改当前局卡牌。
- `app/map-stage.css`、`app/enemy-motion.jsx`：全屏地图悬浮窗口与敌人移动展示。
- `public/manor.png`、`public/rooms.png`：原创宅邸插画和房间图集。
- `tests/game.test.mjs`：规则与通关模拟测试。

远程联机采用 Cloudflare Worker、每房间一个 Durable Object、SQLite 持久化和 Hibernatable WebSocket；解耦边界及逐阶段验收标准见 [远程联机技术方案](docs/remote-multiplayer-plan.md)。

代码或文档变更不自动提交或推送，按项目协作规则提供提交命令。

## 项目目录

```text
app/                 游戏界面、素材室、联机与样式
components/ui/       共用界面组件
lib/                 规则引擎与组件数据
public/              原创美术资源
scripts/             主机服务和离线打包
tests/              自动化规则与联机测试
outputs/             生成的离线游戏（不纳入 Git）
package.json         依赖和开发命令
启动试玩.cmd         Windows 试玩入口
```

运行 `npm ci` 安装依赖，`npm test` 验证规则，`npm run build:portable` 生成离线游戏，`npm run demo` 启动单人／局域网试玩。`npm run dev` 用于开发界面。输出文件位于项目内，迁移文件夹后仍可按相同步骤运行。

Git 仅跟踪源代码、配置、测试、文档和原创素材。依赖、构建缓存、生成的离线文件与本机环境配置均已忽略。提交和推送需要用户明确要求。

项目位置：`D:\dev\house-of-omens`。本地 Git 主分支为 `main`。

此前增加默认伤害分配、交互掷骰、双方权限与防止重复投掷的验证，并用原三个剧本共 36 组新旧流程对比验证相同投掷顺序下的通关结果和随机状态一致。

本轮加入预兆与房间组合触发、狼人剧本、月光与封窗、感染与治疗、狼方追猎目标及阵营胜负。后续试玩反馈修复了地图遮挡、骰子按钮布局、属性变化提示与阵营展示，并明确区分新开定向试玩和继续旧局。48 项自动测试通过，含 64 局狼人模拟和 16 局交互骰对照；标准生产构建与离线单文件打包通过。验证范围见 [狼人试玩说明](docs/werewolf-playtest.md) 与 [本轮试玩反馈修复](docs/playtest-feedback.md)。
