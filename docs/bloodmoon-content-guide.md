# 血月卡牌、房间与机关开发指南

## 正式入口（2026-10-10）

《血月之夜》现已开放普通探索开局、专用游戏集和咬痕正式触发，也支持局域网／远程房间。首页选择血月会自动选用专用牌池；游戏集可复制、编辑、导入，开局前校验必要卡牌。经典游戏集和旧狼人《月光照进来的时候》不变。

分为“游戏集”“咬痕”“单机／联机开局”三项验收，步骤、测试点与本轮提交命令见[分项验收指南](bloodmoon-acceptance-guide.md)。感染、嗜血、追猎和枪械测试现在可直接选择血月剧本，旧菜单中的已有入口仍保留。下列明确标注为试作的规则解释继续沿用，并未因开放入口而自动成为最终设计；资源永久失效与整局平衡仍待决定／验收。

## 追猎、残血与落单（2026-10-10）

新增「追猎方向与残血恢复」「次级狼人追猎」「追猎途中捕兽夹」「落单攻击结果加1」四个定向测试入口。

1. 在追猎测试中，满月初始狼人的普通移动已用尽，远端英雄残血。只有靠近该英雄的长廊可前往，不能使用追猎远离目标；走一步后本回合追猎用完，移动点不会变为负数。
2. 切换角色、重新选中狼人或保存／恢复，不会刷新这1点移动。结束整轮后重新获得。普通移动点优先消耗，追猎只补足合法方向上的不足，房间额外移动费用仍有效。
3. 让目标恢复力量、速度至作祟开始时的数值，追猎入口应消失。判定比较数值而非位置：相邻两格数值相同，仅左移一格不一定残血。
4. 次级狼人即使在初醒阶段也有追猎；初始狼人从满月起才有。追猎不移动速度标记、不增加速度检定骰数，也不能用于探索、电梯或传送。
5. 在陷阱测试中进入长廊，捕兽夹触发并销毁，狼人手动分配2点普通身体伤害，本回合停止移动；不因追猎绕过入场效果。
6. 在落单测试中，另一位英雄在远端：初始狼人攻击骰数不变，最终结果加1；攻击窗口与探索手记明确显示骰子点数及落单加值。让另一位英雄来到双向门直接相连的邻房，加值消失。隔墙、楼梯／传送链接不提供落单保护，死亡角色和其他狼人也不提供。
7. 人物面板显示“残血”“落单”“追猎”的具体悬浮说明。联机只公开残血标记，用于双方一致计算路径；对立阵营无法读取具体属性数值或作祟基准。

实现采用每次实际移动验证连通图距离，不需要先声明目标：仅当这一步缩短到某名存活残血英雄的最短路径，才能使用未消费的追猎点。`pursuitSpentRound` 随存档保存；作祟时用当前规则视图记录 `hauntBodyValues`。旧试作存档缺少这份历史基准，无法准确反推；请重置测试场景后验证残血／追猎，其他原有机制仍能继续。

## 嗜血模块（2026-10-10）

新增「满月嗜血与自由分配」「血月嗜血与第7格上限」「嗜血与银弹永久上限」三个定向测试入口。

1. 初始狼人主动撕咬英雄，先看骰子结果，再由受伤者分配身体伤害，最后处理感染／徽章反应；这些流程结束前不显示恢复选择。
2. 在「嗜血 · 分配身体恢复」窗口逐格选择力量或速度。每个按钮列出当前位置和移动后的格数，剩余恢复格数实时更新；选择一直保留到分配完成或两条轨道均达到上限。
3. 满月最高恢复至第4格；血月最高第7格；受银弹永久削弱后，即使血月也只能到第4格。达到上限后，多余恢复量失效，不降低原本已经高于嗜血上限的标记。
4. 只按实际扣掉的身体轨道格数计算恢复。初醒、次级狼人、反击、手枪和环境伤害不触发；速度恢复不额外赠送当前回合移动点。
5. 分配第一格后保存测试点并恢复，继续分配，检查已恢复部分不重复、结果只记录一次。联机只有初始狼人座位的玩家可以操作，其他玩家看到等待提示。

`lib/content/bloodmoon-bloodlust.mjs` 定义伤害后触发与可序列化逐格分配，复用已有选择窗口和父流程续体；`traitPositionBounds` 统一约束嗜血月相上限和银弹永久上限，不新增独立属性写入通道。

## 感染模块（2026-10-10）

选择「定向测试 → 狼人 → 感染传播与徽章庇护」或「感染Ⅱ检定与净化」。以下测试仍使用独立 `bloodmoon` 战斗模块，旧狼人感染倒计时不变。

1. 在传播测试中让初始狼人撕咬第二位英雄，手动分配伤害；实际身体轨道扣减达到3格才升一级。低于3、伤害被抵消、反击、枪击、蒸汽、陷阱及次级狼人攻击均不传播感染。
2. 第二位英雄已有感染Ⅰ、携带徽章。升级时选择庇护，理智4+成功后仍为感染Ⅰ，不产生感染Ⅱ的属性变化；放弃或失败则正常升级。
3. 每次进入感染Ⅱ使力量、速度右移2格，理智左移1格。观察数值与位置的区别；用同室第三位角色的解药清除后，历史移动不撤销。
4. 在净化测试中切换第二位英雄，结束其回合：先选择净化，降为感染Ⅰ后无需抵抗检定；放弃净化，则投理智3+，成功保留感染Ⅱ，失败转为次级狼人。
5. 转化后检查原属性轨道、玩家座位、下一轮移动及普通攻击；没有月相强化、不死、嗜血或感染传播。全部英雄死亡／转化即狼人获胜。
6. 分别在伤害分配、徽章选择、感染Ⅱ投骰时保存测试点或刷新恢复；后续不重复伤害、升级、属性移动或转化，探索手记记录实际结果。

每次进入感染Ⅱ均执行属性移动；净化优先于感染Ⅱ检定的顺序仍待设计者确认。感染来源由伤害事件的 `sourceHeroId` 和主动／反击标签判定，不从当前选中角色反推。`lib/content/bloodmoon-infection.mjs` 保存传播、状态获得和转化规则；属性仍通过统一接口移动，徽章响应完成后才应用。

## 试玩入口

运行 `npm run dev`，打开终端给出的地址，选择「定向测试 → 狼人 → 血月房间与机关（独立测试）」。

- 首位角色位于实验室，携带戒指、徽章和捕兽夹；三个新房间与地下室平台连通。
- 在实验室尝试制药，行动入口和检定窗口会列出知识 5+ 门槛及药剂效果；投骰后可在同一骰子窗口直接点击可重掷的 0／2 点骰，成功后选择未制备过的药剂。
- 戒指／徽章在实验室或新锅炉房可熔铸为银弹；失败保留材料。
- 进入新锅炉房开阀，结束自己的回合后观察相邻房间蒸汽标记；下一位角色进入或在其中开始回合时检定。
- 同伴位于消毒杀菌室，带感染Ⅱ测试标记，结束其回合可选择净化。
- 捕兽夹可从背包或行动栏布置。让旧狼人沿该房间追猎，可验证路径中途截停与陷阱销毁。徽章可在同室同伴受到旧狼毒感染时尝试庇护。

本场景仍借用旧狼人地图与敌人框架，地图上会同时存在旧锅炉房和新锅炉房；只有新房间具有蒸汽／熔铸动作。测试感染标记不自动升级或转化。选择或投骰期间刷新页面后，从「定向测试 → 继续测试局」恢复。

### 咬痕独立测试

选择「定向测试 → 狼人 → 咬痕攻防与作祟（独立测试）」。本场景从作祟前开始，两名同伴已各获得一张预兆，首位人物正准备收下咬痕，并携带家族戒指。

1. 点击“收下并进行攻防检定”，查看虚拟攻击者的 4 枚攻击骰与角色当前力量对应的防御骰。窗口直接使用咬痕定义中的成功／失败说明。
2. 戒指只允许重掷自己的防御骰；重掷结果持续显示，点击“继续检定”后继续。
3. 攻击方胜出时，完整差值进入身体伤害分配。玩家自行移动力量、速度标记；伤害及相关反应全部完成前，不生成作祟检定。
4. 平局或防御方胜出时，无伤结束，也不产生反击。攻防结果和实际伤害分别记录在探索手记中。
5. 后续作祟检定仍使用当前规则：第一、第二张预兆因为最高点数不足 5 会跳过；本场景咬痕是第三张，可进入作祟检定。若触发，仍进入所选的旧狼人剧本，用于验证流程衔接，不能视为《血月之夜》已完成。

咬痕现设 `scenarioOnly: 'bloodmoon'`，不混入经典或通用扩展预设，可在自定义游戏集中选入，并由血月专用预设提供。正式触发与“咬痕 → 血月正式触发”测试点已开放；旧独立测试保留。沿用“防御方胜出无反击、差值不受旧狼人伤害上限限制”的解释，探索阶段仍遵守属性最低保留第1格的规则。

## 已确认规则

| 内容 | 当前行为 |
| --- | --- |
| 行动机会 | 制药、熔铸、开阀、布夹独立计次，不扣原有互动、攻击、休整机会。制药、开阀、布夹每人每轮一次；熔铸每件材料每轮一次。 |
| 实验室 | Knowledge 5+；成功选择一种未制备的药剂。每种整局最多成功制备一次，使用、丢弃或转移后仍不能重制。失败也扣尝试。 |
| 熔铸 | 实验室／新锅炉房 Knowledge 4+。戒指、徽章各可成功产出一发银弹，合计最多两发。成功销毁材料，失败保留，尝试记录跟随材料实例。 |
| 消毒杀菌室 | 在此结束自己的回合，选择一个可清除负面状态。有等级则降一级，第一级或无等级状态移除；每人整局一次。放弃不扣次数，不撤销历史属性变化。 |
| 家族戒指 | 每轮一次，在检定后的骰子窗口点击持有者自己骰组中一枚 0 或 2 点骰，播放重掷动画后接受新结果。新骰面与整组点数一直留在同一窗口，直到玩家点击“继续检定”，之后才进入原检定后续选择或结算；探索手记记录原点数、新点数与整组结果。放弃不扣次数；交易、丢弃和拾取不刷新。对抗检定可选自己的攻击或防御骰，不能选对方骰组。 |
| 圣者徽章 | 持有者可为自己或同室友方进行 Sanity 4+；成功取消本次可清除负面状态获得／升级，失败照常获得。尝试即扣本轮次数，放弃不扣。多枚徽章按稳定来源顺序响应，成功后跳过其余。 |
| 蒸汽范围 | 开阀者结束本回合时生效，到其下次回合开始时消散。仅覆盖锅炉房旋转后双向门直接相连的相邻房间，不包括锅炉房自身、隔墙房间和楼梯／传送链接。 |
| 蒸汽检定 | 每次开启的蒸汽持续期间，每名角色在每个受影响房间首次进入或开始回合时分别进行 Speed 4+。失败受 1 点身体伤害、当前回合停止移动；重复进入同一房间不重复检定。不同蒸汽分别计时、分别检定，不改变视线。 |
| 捕兽夹 | 布置时从背包取出，友方可见且不会触发。首名敌方移动进入时销毁陷阱、受 2 点身体伤害并停止本回合移动；狼王也会触发，过程显示在移动提示与探索手记中。从已有陷阱的房间开始回合不会触发。可从中途经过的房间触发，不能越过陷阱继续走到路径终点。 |

旧剧本敌人使用 HP，因此旧狼人的环境伤害扣 HP，蒸汽用敌人的速度掷骰；这是旧战斗模型的适配。新可控狼人使用身体属性轨道分配环境伤害，初始狼人适用不死。捕兽夹停止移动，但本身不禁止在触发房间内攻击；不死引起的虚弱攻击限制另行结算。

同一房间的陷阱与蒸汽分别结算，停止移动不会免除已进入房间的其他环境效果。开阀者死亡或转化、无法再开始自己的回合时，其蒸汽在到期轮开始时清理。

## 开发边界与持久化

- `lib/content/bloodmoon-rooms.mjs` 与 `bloodmoon-items.mjs` 保存独立定义。锅炉房的 `BOILER_STEAM_CHECK` 同时提供检定窗口与地图悬浮说明的成功、失败文案；圣者徽章的检定规则放在物品牌的 `check` 字段，按实际目标补足提示。普通事件牌的骰子结果由 `rollOutcomes` 从当前卡牌的成功、失败效果生成。后续房间或物品检定也应由触发源定义完整结果，再交给通用骰子窗口显示。`supply: 'bloodmoon'` 是来源标签；经典预设保持原有牌数和随机数调用顺序，通用扩展和自定义游戏集可显式收录。银弹设置 `deckEligible: false`，仅可熔铸获得。
- `lib/content/bloodmoon-mechanics.mjs` 提供行动、触发器、可序列化 Workflow 及内容结算。通过引擎传入投骰、日志、相邻门、环境伤害服务，不反向导入引擎。
- 人物 `bloodmoonActions` 记录对应动作使用轮次，`sterilizationUsed` 记录整局净化；物品实例 `state.ringRound`、`badgeRound`、`smeltRound` 随交易／丢弃保留。
- `game.bloodmoon.crafted`／`smelted` 是整局生产台账，不能从当前背包反推生产次数。成功结算与材料销毁／产出在同一权威命令内同步完成。
- `game.bloodmoon.steam` 保存每次蒸汽的来源、开启者、房间范围、到期轮次和已检定的角色／房间组合；房间 `traps` 保存陷阱实例、阵营和布置者。
- 联机投影在服务端移除敌方陷阱及其空字段，并隐藏布置日志与对立人物的动作记录；不能只用界面条件隐藏图标。
- 新状态的正常获得／升级使用 `status.gain`，它派发可暂停的 `BeforeStatusGain`，确认未取消后才写入状态。`status.add` 是初始化或已确认结算的底层操作，例如药剂增益、测试初始标记，不触发徽章。血月感染Ⅱ的属性变化在确认状态实际获得后结算，徽章成功阻止升级时不移动属性。
- 含玩家选择的 `status.gain`／`bloodmoon.flow` 不得放入 `effect.atomic`；引擎会明确拒绝。支付与交互流程应分阶段提交，不能用原子批次隐藏异步副作用。
- 选择、检定、到期反应和环境伤害保存父流程续体。伤害未结算完，不提前恢复入场效果；反应恢复不会重走支付、伤害或生产步骤。
- `lib/content/bloodmoon-omens.mjs` 定义咬痕与 `gainAttack` 攻防说明；`cards/gain-attack-workflow.mjs` 复用卡牌获得前后时机，提供虚拟攻击者的对抗检定。`card.gain` 的既有流程版本保持不变，新流程使用独立的 `card.gainAttack` 编号。伤害后的 `contentResume` 保存完整续体，再由权威引擎恢复作祟流程；不通过界面定时器推进规则。携带请求编号的“继续”命令会拒绝过期／重复操作。
- 新回合、角色交接和捕兽夹使用小型、只读的限时事件播报，权威请求仍会阻塞玩家动作；新角色的 `TurnStarting` 效果在交接播报结束后才开始。戒指结果留在原骰子窗口展示。`contentResume` 和敌人阶段内部续体自动推进，不向玩家显示弹窗。
- 敌人移动事件按流程与事件编号只播放一次；移动动画期间暂缓即时伤害通知，抵达后再显示检定或结算，不另弹移动说明窗口。探索手记按投骰、检定、伤害、物品等类别显示，重掷保留前后点数，伤害只在实际完成后记录来源与属性下降。事件播报的文案有对应的结构化手记记录，已由伤害、物品等事件记录覆盖的内容不重复写入。

正常游戏使用 Workflow 执行模式。旧的直算模拟器继续服务旧剧本差分测试；新增反应式内容的完整验收以 Workflow 为准。

## 当前范围

### 可控狼人及月相（2026-10-09）

在「定向测试 → 原狼人剧本」中保留四个独立入口：可控狼人与轨道、满月前夕、血月前夕、次级狼人轨道。它们使用独立的 `bloodmoon` 战斗规则；现在也可从血月剧本进入，血月出现在普通开局和素材库中。原 `werewolf` 剧本与既有预兆组合规则不变，自动游戏集只有选入咬痕才可能通过咬痕触发血月。

初始狼人保留玩家座位和角色回合，不生成 HP 敌人；使用四条独立轨道，初始标记在第4格。次级狼人保留原人物轨道。月相按已完成的完整轮次计算，第3轮进入满月，第5轮进入血月；不会移动标记。新轮移动点、攻防骰数和属性展示共用 `traitRuleView`。角色攻防使用独立且可保存的 `combat.actorAttack` 流程，双方各投自己的骰子，完整差值由受伤角色分配，再根据实际伤害结算感染与嗜血。

### 枪械与弹药（2026-10-09）

通用扩展游戏集增加「手枪」，经典牌堆不变。射击按实际房间坐标、楼层和旋转后的双向门检查直线，不借用楼梯、暗道或移动路径；中间房间有存活角色或敌人即阻挡。普通射程为1～2房间，目标投自己的速度骰，4+闪避；失败进入统一的手动2点身体伤害流程。银弹装填后对初始狼人无限直线射程、自动命中、消耗1发，并进入7点身体伤害分配。

`combat.firearm` 流程保存枪、目标、弹药模式、射线和骰子说明。使用者与目标的骰子／伤害权限沿用现有座位规则。已装银弹存入手枪实例的 `state.loadedBullet`，交易、丢弃、拾取和读档不会复制或丢失弹药。装填／卸下与枪击结果写入探索手记；通知只描述已经发生的事。手枪详情显示当前装填状态，可直接操作射击、装填与卸下。

试作默认：射击占本回合唯一主动攻击；每支枪每回合可装填一次、不占攻击，卸下不退还装填机会；允许同室射击，携带枪和银弹即可直接射击；银弹暂只开放对初始狼人射击，其他目标效果待设计确认。

### 不死与永久上限（2026-10-09）

2026-10-14分配规则修正：普通身体伤害必须先扣减仍能下降的轨道；力量和速度都到第1格后，多余伤害才失效。伤害按钮、完整分配、逐点命令、自动测试和联机服务端共用 `ordinaryDamageLimits` 限制，不能将伤害堆在一项来保留另一项。实际扣减与失效点数分别记入探索手记，银弹继续允许身体属性进入骷髅。

新增验收入口“血月之夜 → 不死与伤害分配限制”：狼人力量第2格、速度第4格，进入入口大厅踩中2点捕兽夹伤害。力量最多分配1点，剩余至少1点扣速度；分配1／1后两项为第1／3格，实际受伤2点，无失效伤害、无新增虚弱。原“普通伤害与不死”入口保留，双身体第1格时普通伤害仍失效并触发下一回合虚弱。旧存档继续使用新校验；已经结算的历史伤害不追溯修改。

`bloodmoon-health.mjs` 提供统一的属性位置边界，属性修改与伤害预览共同使用。初始狼人普通身体伤害最低保留第1格，两项都无法继续下降时多余伤害才失效，实际下降格数与失效点数分别记录。虚弱惩罚在下一次**该角色自己的回合开始**时消耗一次：本回合已经开始时受伤不会扣掉当前攻击；尚未开始自己的回合时受伤，可以在同一完整轮次的稍后回合生效。回合内切换角色和读档不会重复消耗；移动、装填和物品使用仍可进行。次级狼人及英雄没有不死。

人物面板和队伍名单统一显示“虚弱”负面状态，悬浮或点击可查看原因与解除时点。受伤后显示“下次自己的回合不能主动攻击”；限制生效的回合显示“本回合不能主动攻击”，该角色结束行动后隐藏。如果限制期间再次触发不死，下一次自己的回合仍受限。状态由现有 `skipNextAttack` 和 `attackBlockedRound` 字段派生，不额外创建可清除状态，解药不能解除；存档格式和攻击规则保持不变。通知与探索手记采用同一名称。

银弹身体伤害可进入骷髅；初始狼人死亡立即判定英雄胜利。命中存活后，等待完整伤害与反应流程结束，再永久降低力量和速度的最高位置至第4格，并立刻压低超出位置。药剂、休整、通用恢复效果共用此上限；月相保留八格轨道与标记，不能解除上限。第5～7格在人物面板划线标为不可用。永久削弱独立于可清除负面状态，解药不会解除它。

精神属性进入骷髅格会使初始狼人死亡，英雄立即获胜。恢复和伤害来源的扩展应继续经过统一属性／伤害接口，避免直接写 `hero.stats` 绕过上限。

### 本轮手动验收入口

运行 `npm run dev`，打开终端给出的网址，在首页进入「定向测试」，选择旧狼人《月光照进来的时候》，再选择以下独立测试。新测试实际使用 `bloodmoon` 战斗模块；既有狼人测试仍使用原规则。开始后确认试作说明，读只读的回合通知；骰子、伤害分配和物品选择仍需主动确认。

| --- | --- |
