# 《血月之夜》卡牌试作与机制评估

依据：[狼人剧本设计](狼人剧本.md)。日期：2026-09-22。

原《月光照进来的时候》继续使用 `werewolf` 的原有规则。新设计应作为独立剧本接入，不能替换旧狼人、感染倒计时或胜利条件。药剂、解药之后，已接入三张新地图牌、戒指、徽章与捕兽夹，完整新剧本尚未完成。最新规则、试玩入口与开发契约见 [血月房间与机关指南](bloodmoon-content-guide.md)。

## 本轮可试玩的效果

| 卡牌 | 实现 |
| --- | --- |
| 力量药剂 | 自己回合获得持续 1 回合的增益，力量轨道立即右移 2 格，最多到最右格；使用者下次回合开始时回退 1 格且不致死；使用后物品销毁 |
| 速度药剂 | 自己回合速度轨道右移 2 格，规则同上；不额外赠送当前回合移动点 |
| 神智药剂 | 自己回合理智轨道右移 2 格，规则同上 |
| 解药 | 选择自己或同室存活探险者，由使用者逐项选择最多两个可清除负面状态，确认后统一清除并消耗物品 |
| 家族戒指／圣者徽章 | 每轮一次的重掷／庇护，支持选择、放弃、存档恢复、实例计次；徽章可阻止状态升级 |
| 捕兽夹 | 独立布置机会、阵营隐私、敌方首次入场伤害与中途截停 |
| 实验室／锅炉房／消毒杀菌室 | 制药、熔铸、延迟生效的蒸汽、回合末净化；独立地图块，不覆盖旧房间 |

药剂不消耗攻击、互动、休整机会，可以携带、交付、丢弃和拾取。在轨道已满时仍允许按设计使用并消耗。解药可以只选择一个状态，也可以在确认前取消；联机选择超时默认取消，不消耗物品。清除感染不会回退历史属性变化，也不会改变阵营或复活角色。

三种药剂都会留下可见的增益状态，持续到使用者下次回合开始，期间覆盖其他角色和敌人的行动；同轮切换角色不会提前到期。到期移除对应状态，并从该属性的当前所在格回退 1 格，最低为第 1 格（骷髅前一格）。这不是恢复使用前的快照，也不是扣回完整的 2 格：例如第 3 格升至第 5 格，到期降至第 4 格；期间受伤降至第 1 格则不再下降。轨道封顶未获得完整提升时，到期仍按上述规则回退。增益不能被解药清除，存档恢复后只结算一次。速度药剂到期时会校正已经预分配的移动点，按回退后的速度开始新回合。

解药目前针对现有可操作探险者；旧版已经变成敌人的狼人没有这个目标入口。新狼人可控角色模型完成后，是否允许对狼人清除其他负面状态应一并接入。

### 试玩步骤

```powershell
npm run dev
```

打开终端给出的网址，依次进入：

1. 首页「定向测试」。
2. 选择狼人《月光照进来的时候》。
3. 测试场景选择「血月卡牌效果（独立测试）」。
4. 开始后确认作祟说明，在首位角色背包使用三种药剂或解药。
5. 使用药剂后检查人物的增益状态提示；结束整轮并完成敌人阶段，在使用者下次回合开始时确认对应属性回退 1 格、增益消失。

测试场景借用旧版地图和战斗框架；说明中明确标注它不是新剧本。三张药剂和解药直接作为测试资源发放，不混入任何既有剧本的随机物品牌堆。同室队友的感染Ⅱ、中毒和恐惧是解药测试标记，不会自动伤害、升级或转化。感染Ⅱ测试已预先移动属性，用于验证清除后不回退数值。

在解药选择过程中刷新页面后，通过「定向测试 → 继续测试局」恢复选择。需要重试时使用现有测试点／重置场景功能；测试存档与普通局分开。

## 代码边界

- `lib/content/bloodmoon-items.mjs`：首批独立资源定义。`supply: 'bloodmoon'` 阻止这些资源进入默认抽牌堆。
- `lib/content/item-abilities.mjs`：药剂属性提升和解药目标规则。
- `lib/content/triggers.mjs`：通过通用 `TurnStarting` 时机筛选当前角色到期的药剂状态，不依赖旧狼人的感染倒计时。
- `lib/content/item-actions.mjs`：保留原属性目标，同时支持独立 `targetHeroId`，没有将人物目标塞进 `trait`。
- `lib/content/cleanse-workflow.mjs`：可序列化的状态选择、确认、取消流程。
- `lib/status-rules.mjs`：可清除状态判定。已知感染、中毒、流血、恐惧和减速可清除；显式 `removable: false` 优先。其他状态必须同时声明 `negative: true` 和 `removable: true`，避免误删增益或永久削弱。
- `lib/game-engine.mjs`：注册流程与白名单 `status.cleanse` 效果，复用原子物品支付。确认时重新检查目标与状态实例；任一条件失效则不消费物品、不清除其他状态。

选择期间不提前改状态或扣物品。状态清除与使用标记、次数和物品销毁在同一原子批次提交。药剂的属性提升、增益添加和物品销毁同样原子提交；每个增益保存独立状态实例、来源物品实例、属性和到期轮次，到期只移除对应实例。存档仍是 v4；新增流程由当前版本代码识别，进行中的新卡牌存档不保证能由旧程序打开，联机客户端与主机应同时更新。此前试作版本已喝掉的药剂没有增益记录，不追溯补扣；请新开测试局验证新规则。

## 其他机制能否实现

以下区分已接入的独立内容与完整新剧本仍需完成的机制。

| 机制 | 判断与所需改动 |
| --- | --- |
| 咬痕 | 可实现。用户已确认：虚拟攻击者力量为 4，抽牌者以自己的力量防御，双方掷骰对抗。需独立预兆获得流程，先结算差值伤害及伤害分配，再开始作祟检定，不能直接套用仅修改属性的现有预兆效果。攻击不应生成留在地图上的敌人。 |
| 家族戒指重掷 | 已实现。仅持有者自身的0／2点骰，每轮一次；次数随实例流转，放弃不扣次数，接受新结果。独立选择流程支持超过12枚候选骰。 |
| 圣者徽章 | 已实现。`status.gain` 提供可暂停的 `BeforeStatusGain`，可取消添加或升级；多徽章依次响应，成功后不消耗后续徽章。`status.add` 保留为初始化底层写入。 |
| 实验室制药 | 已实现。每人每轮一次独立尝试、Knowledge 5+、成功选择、整局生产台账；已消耗的药剂不能重制。 |
| 银弹制造 | 已实现制造与实例流转。每件材料每轮一次、Knowledge 4+、成功消耗材料并产弹、失败保留，戒指／徽章各最多产一发。装填与射击尚未实现。 |
| 消毒杀菌室 | 已实现回合末选择一个状态降级／移除，每人整局一次，允许放弃。与感染Ⅱ回合末检定的顺序留待感染机制接入时确认。 |
| 蒸汽 | 已实现开阀延迟、直接连门范围、使用者下次开回合到期，每次蒸汽每人每个房间分别检定；失败伤害与停止移动，支持敌人路径中途检定。 |
| 捕兽夹 | 已实现布置、敌对入场唯一触发、路径中途截停、伤害和销毁；联机服务端过滤敌方陷阱信息。旧敌人按HP受伤，未来新狼人需接属性轨道伤害与不死。 |
| 手枪与银弹射线 | 可在地图门位基础上实现同层直线扫描；每跨房间验证双方相对门、检查路径阻挡和距离。普通枪击增加目标 Speed 4+ 闪避流程，银弹独立走自动命中路径。楼梯、传送和可达路径不能替代射线。 |
| 月相属性轨道 | `traitRuleView` 已能覆盖轨道而保留位置，适合切换月相。需补剧本阶段状态、整轮边界和狼人角色模型，所有移动、攻击、展示读取同一规则视图。 |
| 初始狼人／次级狼人 | 需要较大扩展。当前旧狼人大部分逻辑是 `enemies` 的 HP 与自动追击；新设计是四条属性轨道、玩家主动移动／攻击、可分配伤害。应建立可控阵营角色边界并接入座位权限，不能把人物属性映射为一个 HP 数。 |
| 不死与银弹永久上限 | 可实现，需要伤害来源标签、分属性伤害结算、普通伤害最低位置及跳过下一次主动攻击的状态。银弹绕过普通不死保护；存活后永久上限须同时约束药剂、嗜血与其他治疗，不能只限制某一个按钮。 |
| 感染Ⅱ与嗜血 | 可复用实际伤害事件和回合结束时机；需要每次攻击至多感染一次、初始狼人主动攻击来源判断、首次升级属性移动标记。嗜血恢复应依据实际扣除的轨道格数，提供可恢复的自由分配选择，遵守当前月相与永久上限。 |
| 落单／残血／追猎 | 落单可按同室与连通邻房扫描；残血需在作祟开始保存比较基准。追猎移动加值需要声明目标或验证路径，否则可先朝伤者获得加速再转向其他人。 |
| 新剧本胜负 | 单独注册新剧本可行。设计没有旧版的倒计时自动失败，需扩展引擎／界面对「没有轮数上限」的支持；不能沿用旧狼人的 `limit`。英雄击杀初始狼人、英雄全部死亡或转化分别在权威结算点检查。 |

## 正式接入前需要明确的规则

下列尚未明确项影响后续完整剧本；已确认的行动次数、徽章升级和蒸汽首次规则一并记录。

1. **行动预算**：已确认制药、熔铸、布夹、开阀各自独立计次，不共用旧互动机会。枪击是否占每回合唯一攻击机会仍需确认。
2. **咬痕对抗**：攻击方 4 枚骰、抽牌者按力量防御已确认；攻击失败时是否仅无伤结束，以及是否允许反击伤害、是否绕过旧版单次伤害上限，仍需约定。
3. **状态升级**：已确认徽章可阻止感染Ⅰ升级Ⅱ。感染Ⅱ清除后再次达到Ⅱ是否重新获得属性变化，仍需明确「首次」指整局首次还是每次感染周期首次。
4. **回合末顺序**：消毒室净化能否先于感染Ⅱ检定；被普通伤害击倒所失去的「下一回合攻击」如何处理当前回合尚未攻击的情况。
5. **蒸汽首次**：已确认每次蒸汽持续期间，每人每个受影响房间分别检定一次。实现中不同角色开启的蒸汽分别记录，不互相刷新。
6. **射击与遮挡**：同室可否射击；中间房间有任意角色就阻挡，还是要区分房间内位置；银弹能否攻击次级狼人或其他目标；装填是否占行动以及是否能卸下。
7. **精神伤害与不死**：初始狼人 Sanity／Knowledge 到骷髅如何结算；设计只为身体属性规定了不死，英雄胜利却要求银弹击杀，需要明确其他死亡来源。
8. **有限资源失效**：戒指或徽章丢失、材料持有者死亡、银弹无法取回时是否允许继续、回收或直接判负。否则可能存在英雄永远无法获胜但对局不结束的状态。

数值检查：两项身体位置都在第 4 格时，在不进入骷髅的前提下总共只能下降 `3 + 3 = 6` 格，所以 7 点银弹伤害已经必杀。第一发能够存活，需要命中前两项位置提供至少 7 格非致命下降空间。第二发必杀的推导成立，但不意味着每局都需要两发。

## 本轮验证

- 完整 Node.js 测试 264 项通过；本次修改代码的 lint 和格式检查通过，生产构建通过。
- 与本轮修改前版本比较：5 种默认开局及 4 种原定向测试局，分别使用 3／6 人和两个固定种子，共 36 组完整状态一致。
- 原药剂、解药测试继续通过，覆盖到期回退、不可致死、速度移动点校正、自由使用、状态选择、支付、保存恢复和联机权限。
- 新增 17 项测试覆盖资源隔离、地图发现、独立行动次数、生产台账、材料流转、戒指候选骰、徽章阻止升级、净化、蒸汽逐房检定、陷阱隐私和路径截停；包括同室多重环境效果、嵌套流程暂停／恢复、敌人感染反应不重复伤害、最后狼人被陷阱击杀时的胜负顺序。
- 浏览器验证了新房间与行动入口、戒指选择中途刷新恢复、重掷后继续原检定，以及布置捕兽夹后的背包消耗和地图标记。
- 本轮 `npm run test:remote` 通过，包含 WebSocket 同步、迁移、过期和关闭新建后的恢复。受限终端按环境指南将 Wrangler 配置目录指向项目内。

建议下一步实现咬痕，再建立新狼人的可控角色／轨道战斗边界，之后接枪械银弹、感染／嗜血和独立剧本胜负。新房间与信物无需再次实现，但应补新狼人角色模型的适配测试。
