# 动态卡牌与地图悬浮界面

## 试玩操作

- 地图铺满游戏背景，四周各保留一整屏的空白拖动空间。初始镜头对准当前人物所在房间的中心；按住空白或房间拖动可平移，拖动不会误触房间移动；普通房间移动与地图扩展保留拖动后的视角，不再反复自动居中。“回到人物”重新居中，“全图”按楼层范围缩放；这组工具贴近楼层选项卡；宽屏并排，空间不足时自动换到选项卡下方。
- 探索门外空位时，第一次点击只显示空框和“再次点击抽取”，不消耗牌堆或随机数；第二次点击同一空位才抽取房间，再选择朝向并落位。点击另一个空位会更换预览，Esc 取消；切换人物、楼层或推进对局后，旧预览不再用于确认。
- 楼层选项居中悬浮，框内只有楼层名称；该楼层的人物头像在框外下方排列，多人会换行，并保留感染数字。
- 正下方采用游戏式操作区：人物身份章与四行完整属性轨、横向道具槽、独立圆形结束行动按钮。属性的当前数值放大显示，完整轨道常显；不同属性用各自颜色标记当前格和起始格，格子悬停提示对应数值及起始／当前位置，不再常驻图例说明。狼毒、净血保护使用小状态框，悬停或聚焦查看持续时间和效果。道具以不同图标区分，预兆使用紫色边框。悬停道具查看说明，点击固定详情，再点击关闭或按 Esc 收起；使用按钮保留原有规则。展开道具不会撑高底部栏。
- 单人面板跟随当前选中的行动人物；联机时优先显示当前由自己控制的行动人物，其他人行动时保留自己的角色。转化后显示对应敌人的公开生命、力量与移动；原人物物品能力停用。
- 左侧全员栏为按阵营分组的窄人物索引，常显身份章、姓名、楼层、四项当前数值及行动／感染状态。点击只查看资料，在旁边展开完整属性轨与允许公开的物品；另有明确按钮切换行动人物，避免查资料时误操作。怪物条只显示公开生命和位置，隐藏怪物仍用未知项表示。
- 章节、作祟阶段、目标和规则入口默认显示在右上方；探索手记的按钮和独立窗口位于右下方，两者可以同时查看。章节和探索手记共用右侧纵向容器，按可用高度分配空间，内容分别滚动；收起一个后，另一个使用空出的区域。全员栏可独立收起；Esc 收起展开窗口，当前人物状态保留。
- 人物可用行动常驻底部状态栏上方，包括上下楼、目标互动、攻击、休整、封窗和治疗。联机狼方的追猎选择也在此处；行动仍受当前人物、互动次数、待处理事件和联机归属约束。人物行动不再弹出规则与牌堆混合窗口。行动消耗和条件放进按钮悬浮提示，休整收成一个入口后再选择属性；物品使用只在物品栏中进行。
- 牌堆统计移到左下方，显示房间、事件、物品、预兆四种剩余张数；结束整轮保留二次确认与房主权限。
- 测试入口移到最右上设置旁，右上角设置保留声音、骰子动画、素材室和重置测试局。测试窗口只淡入，不通过横向位移入场，避免居中位置跳动。属性变化作为短暂提示浮现。
- 自动投掷前留 0.75 秒准备，开启动画时翻滚 1.5 秒；所有骰子点数揭晓后留 1.4 秒观看，再自动结算并在骰子下方显示结果。窗口打开前已收到骰子结果时也会播放展示，不会误当成动画已经播完。新版默认开启动画，仍可在掷骰窗口关闭；关闭动画也保留观看点数的停顿。结果页只需收起，不再点击“结算结果”。需要选择的伤害分配仍由玩家确认。
- 联机时仍只能投自己负责的骰子。行动方在动画完成后自动提交结算，其他人同步结果。每次结算携带检定编号，重复或过期请求不会再次应用后果。

房间卡牌类型固定在左下角，上下楼通道固定在右下角；抽牌与落位预览复用同一图标布局。左上角集中显示月光、封窗、保险丝和目标旗标；目标不再使用与事件类型相同的星光图案。悬停或键盘聚焦图标会展开独立的详细说明窗，点击图标不会移动人物。房间的 `tokens` 数组可提供 `{ id, icon, label, description }` 标记；`hidden: true` 或 `revealed: false` 的标记不展示。

事件卡点击“掷骰并查看结果”直接开始本次检定，不再先进入空骰窗口再投一次。动画与自动结算停顿保留。无需检定的事件、物品和预兆点击一次就生效，取消重复的结果确认弹窗，改为短暂浮现生效提示，探索手记仍保留记录。需要选择的伤害分配和有效作祟检定会继续出现。`continueCard` 动作携带卡牌队列编号，拒绝过期或重复执行；联机由卡牌所属玩家操作。

## 敌人移动

敌人只在全队结束或主动结束整轮后行动。探索、落位和抽卡本身不会推进敌人回合。

原来的交互骰先展示攻击请求、结算后才更新敌人位置。现在请求包含按真实门和楼梯计算的逐房路径，界面先沿路径播放敌人移动并跟随楼层，然后才打开攻击骰。提示会区分“已经同室，即将攻击”和“本轮未追上”。可跳过移动动画，规则和随机数不受影响；未发生攻击的追猎也有移动过程。攻击骰注明攻击者、受击者和所在房间。

移动演示是结算前的展示，尚未投出的攻击结果不会提前应用。正式结算依然通过同一引擎重放已掷骰子；移动路径不允许穿墙、超过速度或隔房攻击。保存后恢复可重播移动展示，不会重新投已经投出的骰子。

## 动态卡牌接口

`lib/card-rules.mjs` 提供四个入口：

| 接口                                  | 用途                                                               |
| ------------------------------------- | ------------------------------------------------------------------ |
| `resolveCard(game, type, id, heroId)` | 根据当前阶段、剧本和人物返回有效卡牌定义，供展示与实际规则共同使用 |
| `updateCardRule(game, rule)`          | 返回加入或替换指定规则后的新状态，不修改传入状态或基础牌库         |
| `removeCardRule(game, ruleId)`        | 返回删除指定规则后的新状态                                         |
| `cardCureBonus(game, healer, target)` | 计算双方持有的有效治疗加值，同类取最大值、不叠加                   |

规则为可序列化的 JSON，跟随普通存档、测试点和联机快照保存。规则按“基础定义 → 卡牌内置条件规则 → 当前局覆盖”顺序应用；同一字段由最后匹配的规则决定。内置规则位于卡牌的 `rules` 数组，当前局覆盖保存在 `game.cardRules`。更新同一规则编号会替换旧规则。

```js
import { updateCardRule, resolveCard } from './lib/card-rules.mjs';

game = updateCardRule(game, {
  id: 'blood-moon-coffee',
  cardType: 'item',
  cardId: 'coffee',
  heroId: 0, // 可省略，省略时适用所有持有者
  when: { phase: 'haunt', scenario: 'werewolf' },
  patch: {
    title: '双份浓缩咖啡',
    story: '血月下，苦味格外浓烈。',
    effect: '使用后弃置，本回合剩余移动力 +4；不能解除停止移动。',
    useAmount: 4,
    consumable: true,
  },
});
const card = resolveCard(game, 'item', 'coffee', 0);
```

可覆盖字段包括标题 `title`、叙事 `story`、效果说明／直接事件效果 `effect`、获得属性 `trait/delta`、事件检定 `threshold/success/failure`、被动加成 `bonus`、主动用途 `use/useAmount/consumable`、治疗加值 `cureBonus`、作祟能力说明 `hauntText`、抽卡停步 `stopsMovement` 和探索期作祟检定 `hauntRoll`。

`bonus` 支持现有的全检定、攻击、事件、仪式、移动和精神减伤类别；`use` 支持移动、肉体恢复和精神恢复。`success/failure`、事件的对象型 `effect` 沿用引擎效果结构，例如 `{ text: '力量提升两格', trait: 'might', delta: 2 }`。无属性／伤害字段的效果只显示文字。新的动作种类仍需扩展引擎与使用界面，不能把任意函数写进存档。

描述和数值需作为同一条规则一起更新，避免文案与效果不一致。正在投骰时拒绝修改／删除规则，防止投掷时和结算时采用不同定义；卡牌翻开但尚未发起检定时仍可修改。已经结算的获得效果不会追溯重算，被动能力则随当前局势实时解析。

预兆的作祟检定说明已从基础效果中分离为 `explorationText`。探索期显示并按规则执行，作祟开始后不显示、不入检定队列，即使覆盖规则传入 `hauntRoll: true` 也不能在作祟期间重新触发。银色吊坠的治疗能力通过狼人作祟条件规则解锁，说明突出显示，双方持有仍只加一次。

接口供游戏规则模块调用，目前没有添加玩家任意修改正式联机规则的按钮；素材室的自定义草稿仍独立保存。

## 验证范围

新增 10 项自动测试覆盖自动结算完整性与防重、所有预兆阶段切换、动态文案与实际效果、规则持久化、吊坠加值、不合法覆盖、探索不推进敌人回合、移动门路与攻击距离、联机结算权限。另增加地图居中与边界余量、联机个人面板归属和阵营可见性 3 项测试。本轮再增加 3 项掷骰组件初始展示回归测试，覆盖已收到结果仍播放动画、关闭动画保留停顿提示和未投掷状态。另增加 8 项探索预览、地图扩展视角保持、一键事件流程与权限回归测试。再增加 4 项界面静态渲染回归测试，验证道具入口、待处理事件期间仍可查看资料、阵营信息保密、联机行动归属与完整轨道要求。另增加 2 项常驻行动内容与牌堆回合权限回归测试。新增 5 项状态时效与伤害日志测试，覆盖一次性结算、重复请求、死亡、伤害抵消和敌人生命变化。完整测试 92 项通过，游戏代码静态检查、生产构建与离线打包通过。本轮未做浏览器人工视觉验收。

## 伤害与手记

确认伤害分配后，手记记录受伤人物、伤害类型与点数、各项属性的前后数值及格数变化；死亡时仍保留结算记录。精神伤害完全被抵消也会记入手记。攻击敌人记录实际损失生命、厚皮减伤与生命前后值；反击待分配与最终结算分别记录。伤害确认携带请求编号，重复点击不会误分配下一次伤害。手记可滚动查看当前保存的最多 100 条记录。
