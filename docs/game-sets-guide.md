# 游戏集使用与开发指南

游戏集决定一局游戏使用哪些房间、事件、物品和预兆；剧本决定作祟后的目标、敌人及胜负规则。两者独立选择。

家族戒指、圣者徽章、捕兽夹、三种药剂及解药都是通用物品，可用于任意现有剧本。实验室、锅炉房和消毒杀菌室也可作为通用房间加入。源码中的 `bloodmoon` 表示这批内容最初的设计来源，不是剧本限制。银弹属于熔铸产物，不进入随机物品牌堆；当前尚未接入枪械射击。

## 选择和编辑

1. 首页“本局游戏集”选择预设，再开始普通新局。
2. “编辑／导入游戏集”、右上角“设置与菜单 → 游戏集”、素材室的“编辑游戏集”都进入同一个管理界面。
3. 内置“经典游戏集”保持原牌堆；“通用扩展游戏集”在经典内容上加入本轮新物品与房间。
4. 选择一个预设，点击“复制为自定义”，修改名称，按四类牌堆勾选卡牌，然后“保存游戏集”。保存后自动选为下次开局配置。
5. “导出游戏集”下载当前配置的 JSON 文件；“导入游戏集”添加文件中的预设。导入始终创建新副本，不覆盖已有预设；支持删除自定义游戏集。

每种卡牌最多一张。起始大厅、门厅、楼梯与平台固定保留。保存时要求四类牌堆非空、至少 3 张预兆、保留下行楼梯、保留事件和物品抽牌房间，并确保预兆房间数量不少于预兆牌数。校验只保证基本结构，自定义组合仍可能影响探索节奏与平衡。

预兆耗尽时强制作祟按本局选中的预兆总数计算，不再固定按全素材库的数量计算。加入抽牌堆的药剂和实验室制备记录分别管理；随机抽到一瓶不扣制药次数，制药仍是每种整局最多成功一次。

## 存档和联机

- 预设库和所选预设保存在当前浏览器。不同浏览器、地址及设备之间使用 JSON 导入导出传递。
- 普通开局复制一份配置到 `game.gameSet`。编辑或删除预设不会改动进行中的对局；“再来一局”沿用刚结束对局的配置，需要换游戏集时返回开局准备。
- 局域网与远程联机均使用房主创建房间时的配置。服务器验证后保存，加入者看到同一配置和牌数，无需在自己浏览器预装。公开的是候选卡牌，不是洗牌顺序。
- 房间创建后配置固定，切换预设库选择不会改动房间；要换游戏集需重新创建房间。定向测试使用其固定测试场景，不叠加普通游戏集。
- 旧存档及不传游戏集的旧调用继续使用经典行为；显式选择的新局保存配置快照。客户端和服务端需要一起更新以使用此功能。

## 开发接口

```js
import { createGame } from './lib/game-engine.mjs';

const game = createGame('mirror', 123, 3, { gameSet: 'expanded' });
// 自定义配置传入经过 validateGameSet 校验的完整对象：
// { version: 1, id: 'set-example', name: '示例', decks: { rooms, event, item, omen } }
// 四个字段均为已有卡牌定义 ID 的数组。
```

`lib/game-sets.mjs` 统一管理预设、可选定义和校验。`supply` 是来源标签：经典预设排除扩展来源，扩展预设包含可入牌堆的定义。`deckEligible: false` 表示仅由机制产生的物品，不可由游戏集直接抽取。不要通过 `scenario` 判断一张通用物品能否被选择。

`app/game-sets.jsx` 提供共享预设库、选择器和编辑器；素材室、设置、单人及联机开局复用这一入口。浏览器存储键为 `hillhouse-game-sets-v1`，文件包结构为 `{ version: 1, gameSets: [...] }`。最多 30 个自定义预设，导入文件最大 100 KB。

素材室的 DIY 草稿依然用于编辑文案和设计，不自动执行。游戏集只接受已实现定义的 ID，不接收脚本、自定义效果或未知 ID。增加新内容时，先注册规则、补测试，再让游戏集引用；需要多张同类卡或复制房间时，应先扩展对应实例模型，不能直接放开重复 ID 校验。

## 验证

```powershell
node --test tests/game-sets.test.mjs
npm test
npm run test:remote
```

回归覆盖经典行为、通用扩展跨剧本使用、配置快照、非法导入、预兆耗尽、联机权威配置、服务端持久化和隐藏洗牌顺序。浏览器还需检查预设复制、编辑保存、刷新恢复、素材室与设置入口及开局选择。
