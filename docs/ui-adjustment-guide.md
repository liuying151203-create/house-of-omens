## 模块1：骰子与自动续接

运行：

```powershell
npm run dev
```

在首页“定向测试 → 血月之夜”选择对应场景。

1. **咬痕 → 血月正式触发**：先投攻击与防御骰；动画停稳后等30秒，原窗口仍存在，不自动开始伤害或作祟。点击“确认骰子结果”才继续。
2. **家族戒指**：在戒指窗口点一枚可重掷骰，观察动画、新骰面和整组点数。新结果一直保留，点击“继续检定”后才进入原检定后续流程。
3. **制药**：可用原狼人菜单的“血月房间与机关（独立测试）”。在实验室投骰后必须先确认；若使用戒指，再确认重掷结果，成功时最后才出现药剂选择。
4. **自动投掷与关闭动画**：开启自动投掷只代替掷骰。关闭动画立即展示点数，但仍需确认；未投完骰或动画未停稳时禁用确认按钮。
5. **联机权限**：两位玩家各投自己的骰；只有负责该检定的玩家能确认。另一位玩家可看公开结果，但不能跳过或代替确认。
6. **回合／角色切换**：仍使用小型只读播报，期间不可行动；结束后才进入蒸汽等开回合检定。不要出现“继续房间结算”或内部敌人流程大窗口。
7. **重置／回到测试点**：在投骰或通知阶段恢复，不应由旧计时器掷出新请求的骰子，也不应跳过恢复后的选择。结果确认与伤害仍由权威引擎处理。

骰子确认和引擎过期投骰保护单独提交；共用播报组件、页面接入和生命周期测试归入地图与事件过渡提交。请按下方顺序提交，避免遗漏依赖。

## 模块2：扁平暗色展示层

所有新样式集中在 `app/ui-flow.css`，由布局最后加载，不把新颜色散落进多份旧主题文件。本轮是游戏界面、弹窗和通知的基础层，首页美术、地图素材、完整响应式布局和不同窗口的尺寸仍需实际验收。

1. 打开卡牌、骰子、伤害与药剂选择窗口，检查主标题、规则说明和主要操作可清楚区分，药剂文字不与背景混在一起。
2. 弹窗遮罩应允许看见底下地图，没有大范围模糊或强烈缩放；按钮和边框应使用实色，减少原有渐变、金色纹理和重阴影。
3. 骰子确认操作位于窗口底部，长说明可滚动；窄窗口时确认按钮占整行。检查按钮没有被测试点工具或其他内容遮住。
4. 换人／换轮通知位于顶栏下方，应是小型只读提示，不遮挡整个地图，没有确认按钮；保持原有日志记录和流程锁定。
5. 检查人物浮窗、顶部栏、即时反馈与行动按钮的颜色层次，增益／伤害／阵营标记仍有语义区别。
6. 系统开启减少动画时，新弹窗淡入与通知入场停止播放；此设置不改变权威续接时长。

样式包含人物移动、陷阱提示和伤害来源展示，作为视觉基础先提交，随后接入对应功能。

## 模块3：移动后触发效果

首页选择“定向测试 → 血月之夜 → 追猎途中捕兽夹”，完成开局提示后点击地图上的“长廊”。

1. 人物应从原房间移动到长廊，途中不能弹出伤害窗口，也不能连续点击移动或结束回合。
2. 到达后长廊显示捕兽夹标记与边框提示，顶栏下方播报夹子已触发、已销毁、本回合停止移动。此时还未分配伤害，不写“即将结算”或“伤害已扣除”。
3. 提示结束后打开伤害分配窗口。窗口应解释踩中敌方捕兽夹和停止移动；两条属性仍在原位置，待分配2点，确认按钮不可用。窗口不重复展示整段布置捕兽夹的规则。
4. 自行分配力量／速度各1点，或将2点分配给其中一项。点击确认后才扣减属性；探索手记应分别保留移动、陷阱触发、实际伤害记录。
5. 在伤害窗口“回到测试点”，再次进入长廊，完整顺序应正常重播；旧计时器不能跳过新场景。恢复已踩夹的伤害存档时只解释当前陷阱，不重播历史移动，也不重复触发或扣伤。
6. 在“血月房间与机关（独立测试）”中开启蒸汽后进入受影响房间，应先显示人物移动，再开放避开蒸汽的骰子窗口。蒸汽失败后的伤害窗口使用锅炉房同一份检定说明。
7. 普通移动、跨楼层、进房抽卡和坠落共用移动阶段；跨楼层不会画穿过其他楼层房间的直线路径。开启系统“减少动画”时不播放位移动画，操作顺序仍保留。
8. 联机各端从各自可见的结构化事件生成表现队列。流程提示不发送新的规则命令，不读取其他阵营属性；仍需两台设备实际验收播放节奏及网络延迟。

结构上，`lib/map-presentation.mjs` 负责事件顺序与展示位置，`app/map-presentation.jsx` 负责计时和地图阶段锁定；`EventBroadcast` 复用原流程通知的外观。伤害来源文字复用探索手记，蒸汽失败效果引用检定定义。完整卡牌和地图规则保留在各自详情处。权威游戏引擎仍负责实际触发、停止移动与伤害结算，表现队列不修改存档格式或游戏规则。

## 文案精简验收

本轮按已确认的清单精简通知、骰子、制药、卡牌、伤害和探索手记中的重复文字。以下变化只影响展示和记录整理，不改变投骰、确认权限、伤害或药剂规则。

1. 换人通知只显示“轮到某某”；换轮通知保留回合与行动人物。通知不再增加“回合切换”“角色交接”“陷阱触发”等分类行。
2. 骰子停稳后保留骰面、总点数和确认按钮，不显示“已投掷”、重复对勾或结果保留说明。联机仍显示投骰者；没有确认权限时显示“等待某某确认”。
3. 戒指重掷时只显示“重掷中…”。结果保留重掷前后点数、总点数和“继续检定”，不重复解释已经计入结果。
4. 制药检定保留知识5+和成功／失败效果。三种药剂只标明作用于哪条轨道，右移2格、下次回合开始回退1格、不致死及使用限制集中说明一次。选择药剂时同样保留共通规则和整局供应限制。
5. 卡牌通知直接显示名称与效果。单机不重复写结算者，只有停止移动时显示该限制；联机仍保留结算人物。伤害窗口保留待分配数量、属性轨道和致死提示，不再复述“分配X点，下降X格”。
6. 探索手记不再同时显示即时反馈、“最近结算”“最新”和同一事件的过程日志。可确认对应的旧日志合并到结构化记录，移动记录保留剩余移动力，伤害记录保留分配与死亡信息。无法对应的旧日志放入“其他记录”，无结构化事件的旧存档默认展开。原始事件和日志没有删除。
7. 可重测“追猎途中捕兽夹”“血月房间与机关（独立测试）”和“咬痕 → 血月正式触发”，检查必要条件与效果仍可见，结果仍需主动确认。浏览器实际视觉与联机等待仍需试玩验收。

## 按流程决定播报期间是否允许行动

普通结果通知与流程过渡共用外观，但操作权限由 `lib/presentation-requests.mjs` 统一判断，地图、行动栏、物品栏、结束整轮按钮和联机服务沿用同一判断。

- **允许行动**：队列只剩已完成的结果通知，没有后续伤害、投骰、选择、工作流续接，也没有尚未完成的敌人阶段。常见于使用咖啡／绷带、已完成的属性变化或无后续工作的检定结果。通知不拦截鼠标，到时自动消失；新行动可替换通知，每条结果仍保留在探索手记。
- **暂停行动**：换人、换轮、捕兽夹触发、私密交互等待，以及后面还有结算步骤的播报。人物移动与机关触发的本地过渡继续保持“移动 → 触发 → 伤害分配”的顺序；骰子与戒指结果仍需手动确认。
- **联机权限**：已完成通知期间由当前行动者继续操作，不根据通知中提到的角色切换操作权。其他玩家的私密已完成通知不发送内容或阻塞占位；尚未处理的私密选择和伤害继续显示等待占位。新行动替换通知后，旧通知计时器只能携带旧编号，不能推进新的投骰或选择。
- **存档兼容**：沿用现有队列及事件格式，恢复旧通知后同样按队列剩余工作判断权限。行动前逐条完成只读通知的原有收尾检查并保存手记，没有删除日志。

试玩检查：

1. 在旧狼人“作祟开局”测试中使用浓缩咖啡，在“使用浓缩咖啡”通知消失前点击相邻可达房间；移动应立即响应，手记保留使用效果与移动记录。
2. 使用绷带后，在没有其他待结算步骤时直接结束个人回合；通知不应阻挡，随后“轮到某某”的过渡仍会短暂暂停操作。
3. 重测“血月之夜 → 追猎途中捕兽夹”：移动和触发期间仍不开放行动，伤害由玩家分配；确认后若还有后续流程，也不能提前行动。
4. 检定后需要分配伤害、选择药剂或进入作祟时，结果播报不能被移动或结束行动跳过；戒指骰面仍保留到主动确认。
5. 联机当前行动者在普通通知期间可以操作，其他玩家不能代替其结束行动；私密结果不可见，等待伤害／选择时仍不能行动。
